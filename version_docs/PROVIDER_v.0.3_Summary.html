Core Mechanism

Universal Lerp Pattern — How Shocks Are Applied

shock_scale (computed by Environment)

0.0 — Baseline (no shock) 1.0 — Full shock
0.0

effective = 1.0
0.5

# Formula — same in every agent effective = 1.0 + shock_scale × (target − 1.0) # SA Farmer — yield + cost farm_cap = lerp(farm_capacity_bra) fert_fac = lerp(fertilizer_price_factor) qty = base_yield × farm_cap cost = fixed_costs × fert_fac # Transport — throughput + energy eff_cap = capacity × lerp(port_capacity_sa) eff_cost = fixed_costs × lerp(energy_price_factor) # Process — output quantity qty_out = input × ratio × lerp(oil_mill_capacity)

When shock_scale = 0, the formula always returns 1.0 — guaranteed baseline behavior regardless of scenario values.

Temporal Dynamics

Shock Onset & Ramp — Prices Evolve Over Time

Timeline (52 weeks)

Weeks 0–12 — Baseline

shock_scale = 0.0 · All agents at full capacity · Prices at equilibrium level

Week 13 — Shock Onset

Drought begins · shock_scale starts ramping from 0 → 1 linearly over 13 steps

Week 26 — Full Shock

shock_scale = 1.0 · All KG coefficient values fully active · Prices at shocked equilibrium

Weeks 27–52 — Sustained

Shock held at 1.0 · Downstream effects propagate and stabilise

Environment Formula

def update_shock_scale(self, period): onset = self.scenario.shock_onset_step ramp = self.scenario.shock_ramp_steps if period < onset: self.shock_scale = 0.0 elif ramp <= 0: self.shock_scale = 1.0 else: self.shock_scale = min(1.0, (period − onset) / ramp) # Derived output — not an input self.drought_severity = ( self.shock_scale × (1.0 − self.scenario.farm_capacity_bra) )

Called as the first operation each tick, before any agent acts. All agents see the updated shock_scale immediately.

Roadmap

Next Steps — v0.4 Ideas

📡

ShockLoader — Live KG Integration

Currently, KG shock values are manually copied into SimulatorScenarios.csv. The idea: build a shock_loader.py that reads the raw shocks.json output from coypu-kg-analyser parametrize-s1 and automatically writes or patches a scenario row — either directly into the CSV or by generating a new scenario object at runtime.

# Option A — patch the CSV loader.apply_to_csv("SimulatorScenarios.csv", row=2) # Option B — inject at runtime scenario = loader.to_scenario_object(SupplyChainScenario)

This closes the loop: a new KG run → one command → updated simulation scenarios. No manual transcription of coefficient values.

⚖️

Market Clearing

Replace the equal-split flow with price-sensitive allocation. Buyers compare upstream prices and prefer cheaper suppliers; quantity is allocated proportionally. This makes shocks produce non-linear, realistic cascades instead of smooth curves.

Even a simple merit-order clearing (rank by price, fill capacity in order) would dramatically improve scientific credibility before showing results to project partners.

🤖

palaestrAI Integration

Melodie's run() is a blocking loop — palaestrAI needs step-by-step control. Solution: a generator-based run_stepwise() wrapper that yields after each tick, letting an RL agent observe state, pick an action, and step again.

def run_stepwise(self): for t in range(self.scenario.period_num): self._run_one_step(t) yield self.environment.get_state()

Estimated effort: 2–4h. Key open question for Eric: Python-native or Docker + HTTP/OpenAPI interface?

🗺️

Expand to Remaining 8 KG Coefficients

ARG and USA farm groups, Santos port, Rotterdam/Hamburg legs — each requires a new agent group or a separate transport leg in the supply chain. Once added, ShockLoader can map all 14 coefficients automatically.

Prerequisite for full AP 1.3 scenario coverage. Larger refactor — plan in a dedicated session.

📊

Price Calibration

Compare emerged price levels (EUR/tonne soja, EUR/tonne feed) against FAO/WFP commodity indices and MATIF soja futures. Adjust fixed_costs and margin parameters until relative + absolute price levels match historical baselines.

Needed before showing output to project partners or submitting AP 1.3 scenario results.

🏗️

Agent Heterogeneity

Introduce farm size tiers (small / medium / large) with different base_yield, fixed_costs, and drought vulnerability coefficients. Large exporters dominate; smallholders exit first under stress — a key dynamic missing from the current model.

Makes differential impact modelling possible and moves the simulation closer to real supply chain structure.
