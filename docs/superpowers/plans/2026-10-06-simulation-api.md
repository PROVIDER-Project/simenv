# Simulation API Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Accept PDL submissions and expose persistent simulation lifecycle, live progress, running-only lists, and logs through a containerized API.

**Architecture:** A single FastAPI process owns a SQLite job queue and a controller thread. Each simulation runs in a subprocess with private inputs and outputs. Simulation-owned preparation reserves one identifier shared by the API job and simulation run.

**Tech Stack:** Python >=3.10, Melodie, PyYAML, FastAPI, Uvicorn, SQLite, pytest, Docker Compose.

**Spec:** `docs/superpowers/specs/2026-10-06-simulation-api-design.md`

## Global Constraints

- Job ID and run ID are identical, generated by simulation preparation, and never HTTP-client supplied.
- Execute one simulation at a time, retaining the baseline plus PDL scenario behavior.
- One API process/Uvicorn worker per data directory; no external database or broker.
- States are `queued`, `running`, `completed`, and `failed`; persist metadata, inputs, output, and logs.
- `SIMENV_API_DATA_DIR` defaults to `./data/api` locally and `/data` in the container.
- Lists default to limit 50, cap at 100, and use nonnegative offsets.
- Log pagination uses byte offsets, defaults to 16 KiB, and caps at 64 KiB.
- Preserve existing CLI defaults and the existing Postgres Compose workflow.
- Use branch `49-simulation-api`; commit only intended files; PR targets `main` and closes #49.

## Review Focus

- Structurally malformed YAML must produce 422 rather than an internal server error (Task 3).
- Reserved-ID collisions must not overwrite a previous job or its output (Task 1).
- Invalid/truncated progress snapshots must not break monitoring or regress saved progress (Tasks 1–2).
- Shutdown while a worker is launching must not leave a subprocess alive (Task 2).
- A fresh installed package/image must contain simulation templates and scenario resources (Tasks 1 and 4).

## File responsibilities

- `execution.py`: simulation-owned prepared-run context, ID reservation, validation, CLI execution, and progress publication.
- `main.py`: CLI argument parsing and execution delegation, retaining the existing public flags.
- `worker.py`: internal subprocess entry point loading a prepared context.
- `model.py`: optional progress notification after completed simulation steps.
- `api/store.py`: SQLite lifecycle and queue operations, persistent progress, bounded log reads.
- `api/queue.py`: serial subprocess execution, recovery, health, and cleanup.
- `api/app.py`: request/response models, routes, FastAPI lifespan, and dependency composition.
- `Dockerfile.api`, `compose.api.yml`, `.dockerignore`, and `docs/api.md`: deployment and usage.
- Focused tests mirror these boundaries and include a real short simulation integration test.

All Python paths below are under `src/provider_simenv/` unless fully specified.

### Task 2: Persistent queue and subprocess lifecycle

**Files:** Create `api/__init__.py`, `api/store.py`, `api/queue.py`, `tests/test_api_store.py`, and `tests/test_api_queue.py`.

**Interfaces:**
- Consume `PreparedRun`, `load_prepared_run`, and `read_progress` from Task 1.
- `JobStore(data_dir: Path)` with `add(run: PreparedRun) -> dict`, `get(job_id: str) -> dict | None`, `list_jobs(*, status: str | None = None, limit: int = 50, offset: int = 0) -> dict`, `claim_next() -> dict | None`, `finish(job_id: str, *, status: str, error: str | None = None) -> None`, `recover_interrupted() -> None`, and `read_logs(job_id: str, *, offset: int, limit: int) -> dict | None`.
- `SimulationQueue(store: JobStore, *, launcher=subprocess.Popen)` with `start() -> None`, `stop() -> None`, and `healthy: bool`. The launcher injection enables controlled lifecycle tests.
- Public job dictionaries match the spec and expose live snapshots while running, persisted snapshots after termination.

- [ ] Add progress tests: retain last known valid snapshot if a newer read is malformed; final failed jobs retain progress; completed jobs have 100 percent. Assert independent inputs and logs for two submitted runs.
